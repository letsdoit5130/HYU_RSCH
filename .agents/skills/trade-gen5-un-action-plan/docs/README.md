# trade-gen5-un-action-plan — 스킬 문서

> 사용법은 상위 폴더의 [`../SKILL.md`](../SKILL.md)를 참고하세요. 여기서는
> **파이프라인에서의 위치**와 **설계 배경**을 다룹니다.

---

## 1. 파이프라인에서의 역할

5단계 파이프라인의 **마지막 단계(실행 안내 단계)**입니다. 전체 흐름은
[`../../trade-gen-docs/README.md`](../../trade-gen-docs/README.md) 참고.

```
[1] trade-gen1-un-eda 의 EDA 리포트 (우선 개척 시장 3선, 삼국무역 우선 개척 조합 3선, 계절성)
      ▼
[5] trade-gen5-un-action-plan  ← 지금 이 스킬
      │  체크박스 기반 실행 로드맵 생성
      ▼
      사람이 체크하며 실행 → "다음 스텝 진행해줘" → AI가 파일 재확인 후 다음 미체크 스텝 안내
```

**입력**: `trade-gen1-un-eda`가 생성한 EDA 리포트(마크다운). `trade-gen2.1`/`trade-gen2.2`/`trade-gen4`의
소싱 트래커는 직접 읽지 않지만, 로드맵의 "행동" 항목이 그 스킬들 실행을 지시합니다.
**출력**: `{output_dir}/reports/{품목}_Action_Plan.md`

## 2. 왜 새 스킬로 분리했나 (기존 `task-breakdown`과의 차이)

이 프로젝트에는 이미 `@task-breakdown`(MVP → `tasks/task-list.md`) 에이전트가 있지만, 이는
**소프트웨어 개발 라이프사이클** 전용입니다. 무역 실행 로드맵은:
- 입력이 `docs/07_architecture.md`가 아니라 무역 EDA 리포트(시장/마진갭/계절성 데이터)이고,
- "Task"가 아니라 "시장 개척 스텝"이라 계절성 기한, 자금 회수, 샘플 검증 게이트, 중계무역
  법규 확인처럼 무역 도메인 전용 필드가 필요해 범용 Task 스키마로는 표현이 안 됩니다.

따라서 기존 스킬을 확장하는 대신(에이전트-스킬 설계 규칙에 따라 확장을 먼저 검토했음) 도메인
전용 신규 스킬로 분리했습니다.

## 3. 파싱 방식

`trade-gen2.1-un-sourcing`의 EDA 리포트 파서(`parse_eda_report_tables`)와 동일한 철학으로, 정규식
기반 섹션 추출을 사용합니다:
- `## 🎯 1. .... 시장 3선` 섹션에서 `### ①/②/③` 블록 파싱
- `### 🏆 삼국무역 우선 개척 조합 3선` 섹션에서 동일한 방식으로 파싱
- `### 5. 월별 수출입 계절성 분석` 표를 헤더 텍스트에 의존하지 않고 "첫 컬럼이 1~12 범위 정수인
  2컬럼 표"로 인식 (컬럼명이 `refMonth`든 `월`이든 상관없이 동작하도록 설계)

리포트 형식이 바뀌면(예: 헤딩 문구 변경) 파싱이 실패할 수 있습니다 — 이 경우
`generate_action_plan.py`가 `[ERROR]`를 출력하고 중단하며, 빈 로드맵을 만들지 않습니다.
