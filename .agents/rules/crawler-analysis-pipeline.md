# 웹 크롤링 및 데이터 분석 파이프라인 운영 규칙 (Rules)

이 규칙은 타겟 웹사이트를 크롤링하여 데이터를 수집하고, 탐색적 데이터 분석(EDA)을 수행하며, 비즈니스 보고서(.docx, .pptx) 및 대시보드(.xlsx)를 생성하는 파이프라인을 구축하고 실행할 때 모든 AI 에이전트가 준수해야 하는 규정입니다.

## 1. 프로젝트 폴더 구조 및 가상환경 규칙

- 새로운 분석 프로젝트를 생성할 때는 반드시 워크스페이스 루트의 공통 가상환경(`.venv`, `uv` 기반)을 사용해야 하며, 새로운 가상환경을 생성하지 않습니다.
- 새 프로젝트 폴더 하위에는 반드시 다음 4개의 디렉토리를 생성해야 합니다 (`file-folders.md` 규칙 준수):
  - `data/`: 크롤링된 원시 CSV 데이터 및 정제 데이터 저장
  - `docs/`: EDA 보고서(Markdown), Word 보고서(`.docx`), PPTX 슬라이드(`.pptx`) 저장
  - `images/`: EDA 중 생성된 시각화 차트 이미지 저장
  - `src/`: 크롤러, 분석, 대시보드 및 리포트 작성용 파이썬 소스 코드 저장

## 2. 크롤러 (Scraper) 구현 및 실행 규칙

- **User-Agent 우회**: 웹 서버의 봇 감지를 방지하기 위해 신뢰할 수 있는 브라우저 헤더(`User-Agent`, `Referer` 등)를 반드시 헤더에 포함시킵니다.
- **접속 지연 시간 (Rate Limiting)**: 연속적인 요청으로 서버에 부하를 주거나 차단당하지 않도록 요청마다 최소 0.5초에서 2초 사이의 랜덤 대기 시간(`time.sleep(random.uniform(0.5, 2.0))`)을 적용해야 합니다.
- **이어받기 (Resume) 및 중복 방지**:
  - 수집 중 중단되거나 추가 수집을 수행할 때를 대비하여 기존 CSV 파일이 있을 경우 기존 상품번호/도서 ID/기사 ID 등을 불러와 이어받기 및 중복 제거를 수행하도록 구현합니다.
  - 마지막 페이지를 초과하는 요청 시 루프를 자동으로 종료하는 가드를 포함해야 합니다.
- **인코딩**: 엑셀 및 다양한 플랫폼에서 한글 깨짐이 발생하지 않도록 CSV 저장 시 반드시 `utf-8-sig` 인코딩을 적용합니다.

## 3. 탐색적 데이터 분석 (EDA) 및 보고서 규칙

- **EDA 스크립트 (`src/eda.py`)**:
  - 수집된 CSV 데이터를 정제(결측치 대체, 타입 변환, 파생 변수 생성)하고 분석합니다.
  - 최소 5개 이상의 정밀한 시각화 차트를 생성하여 `images/` 폴더에 저장합니다.
  - 마크다운 형태의 EDA 결과 보고서(`docs/eda_report.md`)를 작성합니다. 보고서에는 요약 기술 통계량, 시각화 해석, 비즈니스 관점의 인사이트를 상세히 담아야 합니다.
  - 한글 폰트 깨짐 방지를 위해 `koreanize-matplotlib` 라이브러리를 적극 활용합니다.

## 4. 오피스 리포팅 및 대시보드 규칙

- **엑셀 대시보드 (`src/excel_dashboard.py`)**:
  - `openpyxl` 라이브러리를 활용해 수작업한 느낌이 없는 전문적이고 깔끔한 대시보드를 생성합니다.
  - 데이터 요약 테이블, 피벗 테이블 형태의 분석 시트, 주요 지표(KPI) 하이라이트, 엑셀 기본 포맷팅(통화, 천단위 콤마, 테두리, 배경색 등)을 적용합니다.
- **Word 보고서 (`src/docx_report.py`)**:
  - `python-docx` 라이브러리를 사용해 공식 비즈니스 보고서 형태의 `.docx` 문서를 작성합니다.
  - 제목, 개요, 데이터 기본 현황 표, 주요 분석 결과 및 비즈니스 인사이트를 단락별로 구분하여 깔끔한 서식으로 렌더링합니다.
- **PPTX 발표 슬라이드 (`src/pptx_slides.py`)**:
  - `python-pptx` 라이브러리를 사용해 데이터에 기반한 고품질 슬라이드 장표를 작성합니다.
  - 표지, 목차, 데이터 분석 현황, 핵심 시각화 장표(이미지 삽입), 전략적 제언 및 결론 슬라이드를 구성합니다.
  - 신규 데이터 수집 대상 폴더 개설 시 하위에 자동으로 data/ (원천 CSV/JSON 적재), src/ (코드 소스), images/ (차트 이미지 저장), docs/ (계획서 및 매뉴얼), reports/ (최종 보고서) 폴더를 구조화하여 생성해야 합니다.

## 5. 이벤트 훅 (Hook) 시스템 연동 규칙

- 파이프라인의 무결성을 유지하기 위해 `run_pipeline.py`를 통해 실행 전후 훅을 반드시 수행합니다.
- **Pre-Scrape Hook**:
  - 대상 사이트의 `robots.txt` 정책을 웹에서 긁어와 분석하거나, 타겟 URL에 가벼운 GET 요청을 보내 네트워크 가용성 및 차단 여부를 사전에 검증합니다.
- **Post-Scrape Hook**:
  - 크롤링이 완료된 직후 데이터 크기(행 수)가 최소 기준치(예: 10개 이상)를 넘었는지 검사하고, 중요한 핵심 컬럼의 결측치 비율을 체크합니다. 만약 결측치가 비정상적으로 높다면(예: 50% 이상) 경고를 발생시키고 다음 단계를 일시 차단합니다.
  - 정상 검증이 완료된 경우에만 분석(`eda.py`) 및 리포팅(`excel_dashboard.py` 등) 단계를 자동으로 순차 실행(Trigger)합니다.

## 6. 파이썬 코드 작성 규칙 (Docstring)

- 파이썬 파일(`.py`)을 새로 작성하거나 수정할 때는 반드시 파일 최상단에 해당 파일의 목적, 기능, 입력/출력 인터페이스를 설명하는 docstring을 **한국어**로 작성해야 합니다. (삼중 따옴표 `"""` 사용)
- 한글 인코딩 표준: 한국어 데이터의 호환성 및 MS 엑셀 더블 클릭 시 글자 깨짐 방지를 위해, 모든 출력 CSV 파일은 반드시 utf-8-sig 인코딩을 명시하여 저장해야 합니다.
- 파이썬 파일 생성 시에는 파일 최상단에 # -*- coding: utf-8 -*-을 반드시 명시하며, 주석과 docstring은 한국어로 친절하게 작성합니다.

## 7. 예외처리 및 견고함

- 네트워크 API 요청을 모방하여 데이터를 긁어올 때는 서버 부하와 차단 방지를 위해 반드시 time.sleep(random.uniform(0.3, 0.8)) 과 같은 랜덤 딜레이를 주어야 합니다.
- 서버의 일시적인 429(Rate Limit)나 503 오류 등에 대비하여 지수 백오프(Exponential Backoff) 재시도 로직을 필수 내장하여 예외적으로 파이프라인이 즉시 끊어지지 않도록 방어 설계합니다.
